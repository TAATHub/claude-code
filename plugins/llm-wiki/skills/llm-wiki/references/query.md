# query — Wiki検索・統合回答

`query <質問>` は Wiki 内の関連ページを横断的に検索し、統合した回答を返す。新切り口が出た場合は新ページの提案・作成も行う。

## ステップ1: 関連ページの収集

- `Glob "$WIKI_ROOT/wiki/**/*.md"` で全ページパスを取得
- `Grep` で質問のキーワード（複数バリエーション）を本文・frontmatter `title` 両方で検索
- ヒットしたページの `related` / `sources` をたどって2hop先まで広げる
- ジャンルが絞れる場合は `_overview.md` も読んで全体像を確認

## ステップ2: 統合回答の生成

- 関連ページの内容を読み、質問に対する統合回答をまとめる
- 引用元は必ず `[[ページ名]]` でリンクを示す
- 矛盾する記述があれば「ページA は X と書く一方、ページB は Y と書いている」と並べる（勝手に統合しない）
- ページに無い情報を自分の知識で補う場合は「Wikiには記述なし」と明示する

## ステップ3: 保存判断

[references/decision-rules.md](decision-rules.md) の「query結果を保存する/しない」基準に従って判断する。

### 保存すべきケース

- 既存ページに無い新切り口・視点が出た
- 新コンセプトが導入された
- 再利用性が高い汎用的な分析・比較
- 複数ソース由来の知識を統合する横断的洞察

このときはユーザーに「この回答を新規ページとして保存しますか？」と確認し、合意があれば [ingest.md](ingest.md) のステップ5〜7 を踏む（ソース要約は省略可、`type: synthesis` のページとして作成）。

### 保存不要なケース

- 既存ページの組み合わせのみで答えが出る
- 個別具体的すぎて再利用性が低い（特定の場面でしか使わない計算結果など）
- 既存ページへの軽微な追記で済む

軽微な追記で済む場合は対象ページに直接 `Edit` で追記し、`updated` を today に。

## ステップ4: 完了レポート

- 参照したページ数とパス
- 統合回答（マークダウン本文）
- 保存判断の結果（新規作成 / 既存追記 / 保存なし）
- もし矛盾を検出したら lint へ回す候補として記録

## 検索のコツ

- ジャンルが明らかな場合は `Glob "$WIKI_ROOT/wiki/<genre>/**/*.md"` でスコープを絞る
- 同義語・略語のバリエーションで複数回 Grep する（例: 「インデックス」「index」「INDEX」）
- frontmatter の `type: synthesis` ページは横断知識の宝庫なので優先的に当たる
