# query — Wiki検索・統合回答

`query <質問>` は Wiki 内の関連ページを検索し、統合した回答を返す。新切り口が出た場合は新ページの提案・作成も行う。

## 検索アプローチ

設計思想は [SKILL.md](../SKILL.md) の「検索の方針」を参照。本ドキュメントでは具体的な実行手順を示す。

実行ステップ:

1. **Grep で候補ページ特定** — Wiki 全体をキーワード横断検索
2. **候補ページ Read** — 上位ページを並列 Read
3. **周辺拡張** — 情報不足時のみ、前方/後方リンクで 1hop 広げる
4. **統合回答の生成**
5. **保存判断** — 新切り口が出たときだけ
6. **操作ログ追記**

往復の目安は 2〜3 回（Grep → Read → 必要なら拡張 Read）。`index.md` / `_overview.md` は原則読まない（大きいジャンルでは数十 KB あり、読むだけで検索が重くなるため）。

### Read 上限（コンテキスト爆発防止のハードリミット）

- **ページ Read 上限: 合計 8 ページ**（ステップ2 で最大 5、ステップ3 で追加最大 3）
- 例外的にメタファイル（`_overview.md`）を読む場合もこの 8 枠に含める

### 並列発行の原則

同じステップ内の Grep / Read は **1 メッセージ内で並列発行**する。1 ファイルずつ逐次に読まない。依存があるのはステップ間だけ。

## ステップ1: Grep で候補ページ特定

質問からキーワードを抽出し、**表記ゆれを 1 本の正規表現にまとめて** Wiki 全体を検索する。

- バリエーション: 日英表記・略語・大小文字・カタカナ/英字・同義語
  - 例: `SwiftData|Swift Data|永続化|persistence`
- 対象: `$WIKI_ROOT/wiki/*/*.md`（`index.md` / `_overview.md` / `log.md` はノイズになるので結果から除外して扱う）
- 次を 1 メッセージで並列発行する:
  - `Grep`（`output_mode: "count"`）で本文のヒット数をページごとに取得
  - `Glob` / ファイル名マッチ（ファイル名 = title のため、タイトル一致の強いシグナルになる）
- 質問のジャンルが明らかなら `wiki/<genre>/` にスコープを絞ってよい。ただし絞った結果が 0 件なら全体で再検索する

### 候補の順位付け

1. ファイル名（title）にキーワードを含むページ
2. `type: synthesis` のページ（比較・全体像の質問で優先。ヒット上位から `Grep -l "type: synthesis"` で判定）
3. 本文ヒット数の多いページ

上位 **最大 5 ページ** を候補とする。

### ヒットが 0 件のとき

- キーワードを言い換えて 1 回だけ再 Grep する
- それでも 0 件なら、関連しそうなジャンルの `_overview.md` を読んで知識マップから候補を探す（Read 8 枠に含める）
- なお候補が出なければ「Wiki に該当知識なし」として回答する

### 俯瞰型の質問（「全体像」「比較」「使い分け」「どんな知識がある？」）

ページ単位のキーワードでは拾いにくいので、該当ジャンルの `_overview.md`（知識マップ・横断テーマ）を候補の 1 枠として読んでよい。

## ステップ2: 候補ページ Read

- 候補ページを **1 メッセージ内で並列 Read**
- 読んだ内容で質問に答えられるならステップ4へ進む（ステップ3はスキップ）

## ステップ3: 周辺拡張（情報不足時のみ）

読んだページだけでは答えきれない場合に、そのページの周辺へ 1hop だけ広げる。

- **前方リンク**: 読んだページの `## 関連ページ` と本文中の `[[wikilink]]`
- **後方リンク**: 中心となるページ名で `Grep -l "\[\[<ページ名>"` を発行し、そのページを参照しているページを取得（`sources/` 配下と `index.md` / `_overview.md` / `log.md` は除く）
- 後方リンクの Grep は、中心ページが複数あれば 1 メッセージで並列発行する
- 前方・後方リンクの候補から質問との関連が強いものを **最大 3 ページ** 選び、1 メッセージで並列 Read
- 拡張は **1hop まで**。リンクされていても主題から外れるページは追わない

## ステップ4: 統合回答の生成

- 関連ページの内容を読み、質問に対する統合回答をまとめる
- **引用は3階層で示す**（読み手が検証経路を辿れるようにする）:
  1. **Wikiページ**: `[[ページ名]]` を **主張ごとにインライン引用** する。冒頭まとめだけで済ませない。具体的な事実・数値・人名・年代を述べる文には必ず由来 wikilink を添える
  2. **ソースページ（raw 原文）**: 個別の事実・引用文・統計値を述べる際は、その出典ソースを `[[sources/<genre>/<file>]]` で併記する（Wikiページの frontmatter `sources:` から引く）。`type: source` のソースは raw 原文を保持しているため、**正確な引用・実装サンプル・原典の詳細が必要なときはこのソース本文を直接 Read** すればよい（Read 8 枠に含める）。ただし旧 `type: source-summary` のソースは本文が要約で原文が欠落している場合があるため、逐語引用や実装サンプルの根拠には使わず、`source_url:` の外部 URL を辿って一次情報を確認する
  3. **外部URL**: ソースページの frontmatter に `source_url:` がある場合、または本文中に外部リンクがある場合は、特に「最新性が問われる事実」「論文・公式発表・著者名つき発言」では括弧書きで URL を併記する
- インライン引用の例: 「Werner Vogels が AWS re:Invent 2025 で提起 ([[検証負債]] / [[sources/software-engineering/コードレビューとは何か]])」
- 矛盾する記述があれば「ページA は X と書く一方、ページB は Y と書いている」と並べる（勝手に統合しない）
- ページに無い情報を自分の知識で補う場合は「Wikiには記述なし」と明示する
- 末尾に「**参照Wikiページ**」「**参照ソース**」のリストを付け、本文で言及した全リンクを再掲する

## ステップ5: 保存判断

[decision-rules.md](decision-rules.md) の「query結果を保存する/しない」基準に従う。**既存ページの組み合わせで答えが出た場合（大半のケース）は何も聞かずに次へ進む**。

保存を提案するのは次の場合だけ:

- 既存ページに無い新切り口・視点が出た
- 新コンセプトが導入された
- 複数ソース由来の知識を統合する、再利用性の高い横断的洞察

このときはユーザーに「この回答を新規ページとして保存しますか？」と確認し、合意があれば [decision-rules.md](decision-rules.md) の二分岐（会話由来は [save.md](save.md)、ソース原本があれば [ingest.md](ingest.md)）に従って保存する。query 経由は通常会話起点なので、save がデフォルトとなる。

既存ページへの軽微な追記で済む場合は対象ページに直接 `Edit` で追記し、`updated` を today に。

## ステップ6: 操作ログ追記

参照したページが属するジャンルの `log.md` に追記する。**保存判断の結果に関わらず必ず記録する**。curiosity 動詞がこのログを除外集合として使い、手動 query で活性化したページを次回 curiosity サイクルで重複点検しないようにするため。

### 追記形式

```markdown
## YYYY-MM-DD

- query: <質問の要約（30文字程度）>
  - 参照: [[ページX]], [[ページY]], [[ページZ]]
  - 結果: <no-save / save-rejected / saved as [[新ページ]] / appended to [[既存ページ]]>
```

- 同日の `## YYYY-MM-DD` 見出しが既にあればその下に追記する
- 複数ジャンルにまたがる場合は、**参照ページが属する全ジャンルの `log.md` に同じエントリを追記**する
- 参照ページは Read した全ページを列挙（`_overview.md` / `index.md` / `sources/` は含めない）
- `- 参照:` の形式は curiosity がパースするため変えない
- 結果は 4 種類のいずれか:
  - `no-save`: 保存不要と判定した
  - `save-rejected`: 保存を提案したがユーザーが拒否した
  - `saved as [[新ページ]]`: 新規ページとして保存した
  - `appended to [[既存ページ]]`: 既存ページに追記した

## 完了レポート

回答本文に加え、末尾に 1〜2 行で次を添える:

- 検索経路: `Grep で完結` / `周辺拡張あり` / `_overview.md 参照` / `該当なし` のいずれか
- 保存判断の結果（新規作成 / 既存追記 / 保存なし）
- 矛盾を検出した場合は lint に回す候補として記録

## 検索のコツ

- 正規表現のバリエーションが検索品質を左右する。日本語の概念名と英語の技術名は必ず両方入れる
- ヒットが多すぎる（数十ページ）ときはキーワードを AND 的に絞る（2 語目で再 Grep、または候補ファイルに限定して Grep）
- 後方リンクは「そのページを文脈として使っている応用・事例ページ」を見つけるのに有効
- `_overview.md` を頻繁に読む必要が出るなら、ページのタイトルや本文の語彙が不足しているシグナル。lint で改善候補を確認する
