# save — 直前の Claude Code 会話を Wiki に取り込む

`save [タイトル]` は現在の Claude Code セッションの会話履歴から知見を抽出し、`source_kind: conversation` の source として `sources/<genre>/` に保存して、Phase B（コンパイル）まで実行する。

会話で得られた洞察・設計判断・比較分析などを Wiki に資産化するための入口。WebClipper や URL ingest と並ぶ **第 3 の取り込み口**。

## 引数

| 形式 | 動作 |
|---|---|
| `/llm-wiki save` | LLM が会話全体からタイトル・主題を推定 |
| `/llm-wiki save <タイトル>` | 指定タイトルでファイル名を作成（slug 化）|

引数なしの自動推定モードが基本。明示したい場合のみ引数を指定。

## いつ使うか（適切な対象）

- 概念定義や比較分析が会話で出来上がった
- 設計判断とその理由を残しておきたい
- 失敗事例と学びがまとまった
- ある問題に対する複数案の評価が完結した
- 既存 Wiki ページに対する重要な補足が議論で見つかった

## いつ使わないか（不適切な対象）

- 会話が短く、保存価値のある内容が含まれていない
- ユーザーへの問い合わせや確認のやり取りだけ
- 単なるコマンド実行のログ
- 個人的な意思決定の備忘（Wiki ではなく別のメモへ）

判断に迷ったら **保存しない側に倒す**。後から思い出して `save` し直すこともできる。

## 処理フロー

### Step 1: 会話の要点抽出

現在の Claude Code セッションの会話履歴から、知識として保持価値のある内容を抽出する。

**抽出対象**:

- 確立した概念定義
- 比較表・評価軸
- 設計判断とその根拠
- トレードオフ分析
- 既存 Wiki ページへの重要な補足
- 失敗事例と学び

**抽出から除外**:

- 雑談・確認のやり取り
- 行ったり来たりした検討の途中過程
- ユーザーの好み確認・意思決定の備忘
- コマンド実行ログ
- 既に確定済みの事実の再確認

抽出結果は **要点リスト**としてまとめる。これを次ステップで raw ソース（議論サマリの生テキスト）に整える（過度に圧縮せず、論点・結論・根拠を保持する）。

### Step 2: 保存価値の判定

抽出結果に基づき、保存に値するか判定する:

- 抽出が 3 行未満なら **保存しない**（ユーザーに「保存価値のある内容が見つかりませんでした」と報告して終了）
- 抽出が既存 Wiki ページの軽微な補足のみで完結する場合は、**直接該当ページに `Edit` で追記** して終了（ソースファイルは作らない）
- それ以上の規模なら次ステップへ

### Step 3: タイトル決定

引数指定があればそれを使用。なければ抽出内容から推定:

- 会話の中心トピックを 10〜30 文字程度で表現
- 既存ソースや Wiki ページと重複しないか確認
- 衝突したら接尾辞で区別（例: `LLM Wiki設計議論-2026-05-06`）

### Step 4: ジャンル判定

抽出内容の主題から最も適切なジャンルを推定（[references/ingest.md](ingest.md) の A-3 と同じ自動振り分けロジック）:

- 既存ジャンル一覧を `Glob "$WIKI_ROOT/wiki/*/"` で取得
- 主題が既存ジャンルのどれに最も近いかを判断
- 確信度に関わらずユーザー確認は行わず自動採用。低/該当なしは新ジャンル候補の第 1 スラッグで `init <genre>` を自動実行
- 採用ジャンル・確信度・判定根拠は `save` の完了レポートに必ず記録する（確信度「中」「低」は「要レビュー事項」にも併記）

> `save` は会話文脈からジャンル推定が高精度に効くため `inbox/` を経由せず直接 `sources/<genre>/` に書く。`inbox/` triage フローは「外部から取り込まれてジャンル不明な状態のソース」を対象とした設計で、save の責務とは異なる。

### Step 5: 会話を raw ソースとして保存（type は未設定のまま）

会話の一次ソース（＝原本）は会話そのもの。これを **整形した議論サマリの生テキスト**として `sources/<genre>/` に保存する。**3〜10 行へ圧縮した「要約」にはしない**——論点・結論・判断・その根拠を、後から原文として再利用できる粒度で**そのまま残す**（実装サンプル・コード断片・具体的な数値や固有名が会話に出ていれば逐語で含める）。要約・主要トピックへの構造化は wiki ページ側（Step 6）が担う。

本文は `type: source` の raw 扱い。**ただし `type: source` フィールドはまだ立てない**（Step 8 完了印として最後に立てる）。`generated_pages` は Step 6 の結果を Step 8 で書き込む（Step 5 時点では空でよい）。

`$WIKI_ROOT/sources/<genre>/<title-slug>.md` を新規作成:

```yaml
---
title: "<タイトル>"
genre: <genre>
# type: source は Step 8 末尾で立てる（途中失敗時に再検出させるため）
source_url: "claude-code-session"
source_kind: conversation
fetched_at: <today>
generated_pages: []     # Step 6 で生成/更新した wiki ページを Step 8 で列挙（Step 5 時点では空配列のまま）
created: <today>
updated: <today>
---

# <タイトル>

> Claude Code 会話セッション（<today>）の議論サマリ（生テキスト）。要約ではなく原文資産として保持。

<会話で確立した内容を、整形しつつも圧縮しすぎずに残す。
問い → 検討の要点 → 結論・判断 → 根拠 の流れで、具体例・コード・数値・固有名は逐語で含める。
構造化された wiki ページとは別に、ここには「会話で実際に何が言われ何が決まったか」を一次情報として残す。>
```

途中失敗時の冪等性: Step 5 で作ったソースファイルは `type` が未設定のため、再度の `/llm-wiki ingest`（引数なし）で **未取り込みとして検出され、Phase B が補完実行される**。save の Step 6 以降が失敗しても安全に復旧可能。

### Step 6: Wiki ページの作成・更新（ingest の B-1〜B-3 相当）

[references/ingest.md](ingest.md) の Phase B-1 〜 B-3 と同じロジック:

- B-1 相当: 既存 Wiki 状態の把握
- B-2 相当: 要点抽出（Step 1 と一部重複するが、Wiki への接続を意識して再評価）
- B-3 相当: Wiki ページの作成・更新（[references/decision-rules.md](decision-rules.md) に従う）

**会話由来の保存は基本的に `type: synthesis`** として作成する（複数ソース由来の統合知見の系譜）。会話で初めて確立した概念で十分な情報量があれば `type: concept`、特定エンティティの分析なら `type: entity` も可。

なお、save では ingest の B-4（ソース frontmatter の整備）に相当する作業を Step 5 / Step 8 で行うため、独立した B-4 ステップは踏まない。raw 本文は Step 5 で確定済みで、以降は触らない。

### Step 7: `_overview.md` 更新判定

[references/ingest.md](ingest.md) の B-5 と同じトリガー条件。会話由来は **横断的な視点** を持ちやすいので、`## 横断テーマ` セクションへの追加が発生しやすい。

### Step 8: index 更新 → type 立て → log 追記（最終ステップ）

順序（index 更新 → type 立て → log 追記）を踏む。設計上の理由（冪等性確保のため type 立てを後段にする）は [ingest.md](ingest.md) の B-6 を参照。

1. `wiki/<genre>/index.md` の「ページ一覧」（または該当カテゴリ判断不能なら「## 未分類」）に新規ページを追記、frontmatter `updated` を today に
   - 追記フォーマット・カテゴリ振り分け・「## 未分類」の扱いは [conventions.md](conventions.md) の「ジャンル index (`index.md`)」セクションが正典
   - サマリは Step 1 の要点抽出から生成する
2. Step 5 で作成したソースの frontmatter に `type: source` を追加し、`generated_pages` に Step 6 で生成/更新した wiki ページを列挙（save の完了印。raw 本文は触らない）
3. `wiki/<genre>/log.md` に追記:

```markdown
## <today>

- save: [[sources/<genre>/<title-slug>]]（会話由来）
  - 新規: [[ページA]]
  - 更新: [[ページB]]（<理由>）
```

## 完了レポート

- 取り込んだ会話のタイトル
- 抽出した要点の件数
- 新規 / 更新した Wiki ページ
- `_overview.md` 更新の有無
- 保存価値が低くて打ち切ったセクションがあればその件数

## ingest / recompile / save の使い分け

| 動詞 | ソース | 起点 | 主用途 |
|---|---|---|---|
| `ingest` | Web Clipper / URL / 手動ノート | 外部の文書 | 記事・論文・コードを Wiki 化 |
| `recompile` | 既存ソース（`source`/`source-summary`） | 既に取り込み済みのソース | スキーマ進化への追従 |
| `save` | 現セッションの会話 | Claude Code 対話そのもの | 議論・分析・設計判断の Wiki 化 |

## エッジケース

### 会話が長すぎてコンテキストが切れている

セッションのごく直近しか覚えていない場合、それ以前の議論を Wiki 化したいなら `save` ではなく **手動でソースファイルを作成 → ingest** が現実的。`save` は「現在のコンテキストにある会話」を対象とする。

### 会話の中で複数の独立トピックが扱われた

ユーザーに分割を提案:

```
複数トピックを検出: 「A の設計」「B の比較」「C の問題」
→ 1 つの synthesis ページにまとめる / 各トピックを個別に save する / 主要トピックだけ save する
どちらにしますか？
```

### 既に同じトピックのソースが存在する

ユーザーに以下を確認:

1. 別 slug で新規（例: `<title>-2026-05-06-2`）
2. 既存に追記マージ（既存ソースを読み、追加要素だけ Edit で追記）
3. スキップ

### 抽出が薄い

「保存価値のある内容が見つかりませんでした。会話を続けてから再度 save してください」と報告して終了。誤って空のソースファイルを作らない。
