# 判断基準

ページの新規作成・既存更新・分割、および query 結果を保存するか否かの判断基準。Karpathy の LLM Wiki 思想に沿う。

## ページ新規作成の判定（三条件すべて）

新しいページを作るのは、以下を **すべて** 満たすとき。

1. **未独立**: そのコンセプトに対する独立ページが Wiki に存在しない
2. **十分な情報量**: 既存ページの1セクションに収まらない量・深さの情報がある
3. **再利用性**: 複数ページから参照される見込みがある（自分自身で参照を作るのも可）

1つでも満たさない場合は新規作成せず、「既存ページ更新」または「保存しない」を選ぶ。

## 既存ページ更新の判定

既存ページを更新するのは、新しいソースまたは知見が以下のいずれかを満たすとき。

- 既存記述に **直接関連** する追加情報を含む
- 既存記述を **補強・修正・矛盾指摘** する情報
- ページの欠落セクションを埋める情報

このとき:
- frontmatter `updated` を today に
- frontmatter `sources` に新ソースを追加
- 矛盾を含む場合は「## 異論・補足」セクションを追加（既存記述を消さず両論併記）

## ページ分割の判定（三条件すべて）

既存ページを2つ以上に分けるのは、以下を **すべて** 満たすとき。

1. 既存ページの1セクションが **肥大化**（目安: そのセクション単体で500〜1000字超）
2. そのセクションが **独立トピック** として成立する（他のページから単独で参照可能）
3. 分割によって **理解しやすさが向上** する

分割の作法:
- 切り出した内容を新ページとして作成（[conventions.md](conventions.md) のテンプレートに従う）
- 元ページのセクションは「## <トピック> → [[新ページ]]」のような要約 + リンクに置き換える（完全に消さない）
- 元ページの `related` に新ページを追加
- 操作は `log.md` に「分割: [[元ページ]] → [[新ページ]]」と記録

## 横断ページ（synthesis）の作成タイミング

`type: synthesis` のページは LLM Wiki の真価。複数ソースから得た知見を統合する。次のサインで作成を検討する。

- 複数のソース要約に同じテーマの記述があり、各ソースで異なる切り口で語られている
- ジャンル内の3ページ以上で同じ問題を扱っているが、横断的な整理ページがない
- query で「比較」「使い分け」「全体像」を問われた

例: 「インデックス戦略」が SELECT最適化・WHERE最適化・Range最適化 の3ページから知見を統合する横断ページ。

## query 結果を保存するか否か

### 保存すべき（新ページ化）

- Wiki にない **新切り口・視点** が出た
- 新しい **コンセプト** が導入された（既存ページの単純拡張ではない）
- **再利用性が高い** 汎用的な分析・比較
- **複数ソースの統合** から生まれた知見

このとき `type: synthesis` のページとして保存する。query 結果保存はほぼ会話起点なので、通常は [save.md](save.md) で現セッションを取り込む（会話要点抽出 → Wiki ページ作成・更新までを一括処理）。手元にソース原本があるなら別途 [ingest.md](ingest.md) を回す方が source-summary も残るため望ましい。

### 既存ページに追記する

- 既存ページの軽微な補足・例示
- 質問特化の言い回しではあるが、内容は既存ページに足すべき性質

このときは対象ページを `Edit` で更新し、frontmatter `updated` を today に。

### 保存しない

- 既存ページ知識の組み合わせ・要約のみ（読み返したいなら元ページを見ればよい）
- **個別具体的すぎ** て再利用性が低い（特定の状況でしか使わない計算・コード断片）
- ユーザーの意思決定の備忘（Wiki ではなく別所のメモに残すべき）

## 判断に迷ったら

- 迷ったら **保存しない** 側に倒す（後から ingest できる）
- 既存ページ更新 vs 新規作成で迷ったら、まず既存ページに追記する。後で肥大化したら分割すればよい
- 重要なのは Wiki の **信頼性**。確証のない情報を書くくらいなら書かない
