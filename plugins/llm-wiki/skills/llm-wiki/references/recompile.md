# recompile — 取り込み済みソースの再コンパイル

`recompile <パス>` は **既に取り込み済み** の source-summary を、現在の Wiki 状態に対して再評価し、Wiki ページを更新する。

## 用途

通常の `ingest` は `type: source-summary` 済みのファイルをスキップする。次のような場面で過去のソースを再評価したいときに使う:

- `_overview.md` の知識マップを進化させた後、過去のソースを新しい構造に当てはめ直したい
- `decision-rules.md` を更新して、以前「保存しない」と判断したものを再判定したい
- 既存の Wiki ページ A を分割した後、A を sources にしていた他の source-summary の `[[ページA]]` リンクを更新したい
- frontmatter スキーマを変更した後、既存ソースを新スキーマに合わせて整え直したい

**通常運用では使わない**。月次メンテや構造変更時のみ。

## 引数

`<パス>` 必須。引数なしの全件 recompile は **意図せず大量更新が走る危険があるため許容しない**。複数件をまとめて再処理したい場合はユーザーが明示的にループする。

```
/llm-wiki recompile sources/ai/Claude Code Agent Teamsの衝撃と実際.md
```

## 前提条件チェック

実行前に対象ファイルを Read し、次を確認:

- パスが `sources/_inbox/` 配下でないこと
  - `_inbox` 配下が指定されたら「ジャンル未確定です。`/llm-wiki ingest <パス>` で triage してください」と案内して終了
- `type: source-summary` が立っていること
  - 立っていなければ「未取り込みです。`/llm-wiki ingest <パス>` を使ってください」と案内して終了
- `genre` フィールドが設定されていること
- `sources/<genre>/` 配下にあること

## 処理フロー

[ingest.md](ingest.md) の **Phase B（コンパイル）** を、既存の source-summary を入力として再走させる。

### 1. 前回のコンパイル結果を把握

- `wiki/<genre>/log.md` から「このソースから生成・更新したページ」エントリを抽出
- source-summary 本文の「ソースから生成・更新したWikiページ」セクションを読む
- 前回触ったページのリストを得る

### 2. 既存 Wiki 状態の最新化

ingest.md B-1 と同じ:

- `wiki/<genre>/index.md` を Read
- `_overview.md` を Read
- 関連しそうな既存ページを `Grep`

### 3. 要点の再抽出

source-summary の「元コンテンツ（要旨）」セクションと「要約」セクションをベースに、現在の Wiki 構造に対する位置付けを再評価。

### 4. 差分計算

| 項目 | 前回 | 今回 | アクション |
|---|---|---|---|
| 新ページ A | 作成 | 不要（他ページに統合済み） | 何もしない（既存はユーザーが整理した結果として尊重） |
| ページ B | 更新 | 追加更新 | Edit で追記 |
| ページ C | 言及なし | 関連発見 | Edit で追記 + `related` に追加 |
| 分割: D → E | 完了 | E が他ページと統合された | source-summary のリンクを E から統合先に更新 |

**既存 Wiki ページの構造はユーザーの意思を尊重する**。recompile が勝手に新ページを作り直したり、既存の整理を上書きしてはいけない。基本は **追記と相互リンク補強** に留める。

### 5. `_overview.md` の更新判定

[references/ingest.md](ingest.md) の B-5 と同じトリガー条件を適用する:

- 新カテゴリが必要になった
- サブカテゴリ細分化が妥当
- 構造変化（分割で上位概念が浮上）
- 横断テーマの追加

該当する場合のみ `_overview.md` を更新。recompile は「既存構造を尊重する」原則なので、**ingest 時より更新条件を厳しく**設定する（迷ったら更新しない）。

### 6. source-summary の更新

- frontmatter `updated` を today に
- 「ソースから生成・更新したWikiページ」セクションを最新の Wiki 状態に合わせて書き換え
- リンク切れがあれば修正

### 7. log.md に追記

```markdown
## <today>

- recompile: [[sources/<genre>/<source-slug>]]
  - 更新: [[ページB]], [[ページC]]（<理由>）
  - リンク修正: [[元ページD]] → 統合先 [[ページE]]
```

## 安全側のルール

- **新規ページの作成は原則しない**。recompile は「既存 Wiki への接続を更新する」役割。新コンセプトが見つかった場合はユーザーに「新規ページとして切り出すか」を確認
- **既存ページの破壊的書き換えはしない**。Edit による追記のみ。セクションを丸ごと差し替えたい場合はユーザー確認
- **大量 recompile を避ける**。1 ファイルずつ。複数件を回す場合は各ファイルの結果をユーザーに確認しながら進める
- **`index.md` のカテゴリ再編は recompile の範疇外**。ページ分類の見直しが必要な場合は、別途手動編集または lint 結果に基づく再分類フローで対処する。recompile は既存ページ間の相互リンク補強と source-summary 更新に専念する

## 完了レポート

- 再コンパイルしたソース
- 更新した Wiki ページのリスト
- リンク修正した箇所
- ユーザー確認が必要な事項（新コンセプト発見、構造変化など）

## ingest との違い

| 観点 | ingest | recompile |
|---|---|---|
| 対象 | `type` 未設定のソース | `type: source-summary` 済みのソース |
| 引数なしモード | あり（全件スキャン） | なし（必ずパス指定） |
| 新ページ作成 | 積極的に行う | 原則しない（ユーザー確認必須） |
| 既存ページ書き換え | 追記中心、必要なら分割 | 追記と相互リンク補強のみ |
| `_overview.md` 更新 | トリガー条件に該当すれば更新 | より厳しい条件で更新（迷ったら更新しない） |
| 用途 | 日常運用 | メンテナンス |
